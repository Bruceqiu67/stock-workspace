# 每日三框架市场扫描与趋势预判

## 用途

在用户要求「分析今日大盘走势+明日预判」时使用。与 mi-skill 主 SKILL.md 中「全市场扫描快速通道」的区别：

| 扫描类型 | 输出 | 数据需求 |
|---------|------|---------|
| 全市场扫描（选方向） | 候选方向 + 初筛结论 | 板块排行 + 新闻催化 |
| **盘前简报（参见 §盘前简报工作流）** | **隔夜外围 + 昨日A股 + 今日关注 + 持仓参考** | **premarket JSON + MCP实时行情 + web_search新闻** |
| **每日市场扫描（本文件）** | **大盘走势 + 资金分析 + 明日预判** | **指数数据 + 外围行情 + 情绪验证** |

## 工作流

### Step 1: 获取主要指数数据（1次 curl）

使用腾讯 `qt.gtimg.cn` API 获取所有主流指数的一站式数据：

```bash
curl -s "http://qt.gtimg.cn/q=sh000001,sz399001,sz399006,sh000688,sh000300,sz399303,sz399852"
```

**关注指标**：

| 指数 | 代表 | 今日关键信号 |
|------|------|-------------|
| 上证/深成 | 整体大盘 | 涨跌幅 + 振幅 |
| 创业板指 | 成长股 | 振幅大于主板说明分歧大 |
| **科创50** | 科技方向 | **最关键的领先指标** — 若科创50逆势收红，说明科技方向有独立逻辑 |
| 沪深300 | 蓝筹/权重 | 若跌幅<小盘指数 → 权重护盘 |
| **国证2000/中证1000** | 小盘股情绪 | **跌得比主板多 = 散户恐慌，跌得比主板少 = 情绪修复** |

### Step 2: 检查外围市场（1次浏览器扫描）

从东方财富行情页面的全球股市板块读取关键外围指数：

- **韩国KOSPI**: 亚太科技股风向标，若跌幅>A股说明A股已有独立逻辑
- **日经225**: 亚太整体情绪
- 同时注意页面头条/标题是否有全球性利空（如"芯片股抛售潮席卷全球"）

**判断框架**：
- 韩日大跌 + A股科创抗跌 → **A股科技已独立于全球周期，相对强势**
- 韩日大跌 + A股全面跟跌 → **外部压力传导中，需谨慎**

### Step 3: 热股情绪代理（1次批量curl）

当板块排行API不可靠时（boardlist URL redirect 或 push2 clist 返回空），使用**热股情绪代理法**——选取 8-10 只代表不同方向的核心个股，批量获取实时涨跌幅，从而推断板块轮动。

**标准代理列表**：

```python
hot_stocks = {
    "sz002371": "北方华创(半导体设备)",
    "sh688981": "中芯国际(晶圆代工)",
    "sz300502": "新易盛(光模块)",
    "sz002050": "三花智控(机器人)",
    "sz002472": "双环传动(机器人)",
    "sh600276": "恒瑞医药(创新药)",
    "sz000977": "浪潮信息(AI服务器)",
    "sz300059": "东方财富(证券)",
}
```

**推断规则**：
- 半导体(北方华创/中芯)逆势红 → 科技主线健康
- AI算力(浪潮)领涨 + 证券(东财)大跌 → 资金在集中到确定性方向
- 机器人(双环/三花)大跌 → 短期获利回吐，非基本面变坏
- **板块强弱差**：如果最强板块（如浪潮+1.94%）和最弱板块（如东财-4.20%）相差 >5%，说明市场极度分化，非普涨/普跌格局

### Step 4: 三框架综合

| 框架 | 分析维度 | 关键问题 |
|------|---------|---------|
| **Serenity 产业链视角** | 方向轮动 | 今日领涨的逻辑是什么？是产业真启动还是题材炒作？ |
| **Serenity 研究方法论** | 资金+情绪 | 成交量是缩是放？散户情绪如何？是否有外部催化？ |
| **mi-skill 资金流** | 趋势+买卖点 | 指数日内走势（探底回升/冲高回落）透露了什么主力意图？ |

### Step 5: 明日预判输出

输出格式：**两种情景 + 概率 + 关键区间**

```
明日两种情景：
| 场景 | 概率 | 触发条件 |
|:----|:----:|---------|
| 探底回升收小阴/小阳 | 65% | 早盘惯性下跌后，XX方向继续抗跌 |
| 继续中阴下跌 | 25% | 外围突发利空 |
| 直接反弹收阳 | 10% | 政策利好催化 |

关键区间：
- 支撑：XXX（今日最低下方）
- 压力：XXX（今日高点附近）
```

在输出明日预判后，**自动执行**以下操作记录预判：

```python
# 由 Hermes 在输出预判后自动调用 execute_code 或 terminal 执行
```

### Step 6: 完整报告输出模板

在完成所有数据采集后，按以下结构输出**全市场三框架分析报告**。注意此模板与 mi-skill 主 SKILL.md 中的「持仓诊断」「个股推荐」等模板不同——这是**全市场视角的日报**，用户看到的是"今天市场怎么了"而非"我的股票怎么了"。

#### 报告结构顺序

```
# 📊 三框架全市场分析报告 · YYYY年MM月DD日（周X）

## 一、大盘全景（mi-skill 量价分析）
   - 指数数据表（收盘/涨跌/振幅/成交额）
   - 两市合计成交额
   - 分时节奏描述（今开→高→低→收的时间顺序）
   - 量价结构深度拆解（表格形式：振幅/量能/MA5/高低点/大小盘分化）
   - mi-skill 量价判断（一句话结论）

## 二、情绪与资金维度（Serenity 研究方法论）
   - 全球联动（外围主要市场表现 + 对A股传导判断）
   - 北向/南下资金（沪港通/深港通状态）
   - 情绪温度计（表格：指标/数值/定级，用 🟢🟡🔴 三色）
   - 综合情绪结论（一句话定级）

## 三、方向与轮动（Serenity 产业链视角）
   - 热股情绪代理结果（8-10只标杆股涨跌幅表，标注领涨/领跌）
   - 方向轮动矩阵图（ASCII 表格分"逆势走强/温和调整/领跌/方向判断"四象限）
   - Serenity 产业链解读（资金三路配置分析：避险/主线/兑现）

## 四、三框架综合预判 · 明日走势
   - 技术面关键位（压力/支撑区间）
   - 情绪面判断（外围/北向/小盘杀跌极值）
   - 产业链面判断（引领方向+受阻方向）
   - 全面预判（两种情景+概率+触发条件+关键区间）
```

#### 核心数据原则

- **科创50是最领先的指标**：若它逆势收红，应高度关注。今日预判中要把科创板独立逻辑放在突出位置。
- **大小盘分化是情绪关键**：国证2000/中证1000 跌幅 vs 沪深300 跌幅的差值 >1% 即说明市场极度分化，不是普跌格局。
- **外围联动要区分传导强度**：韩日暴跌但A股科创50抗跌 → 国产替代独立逻辑；全面跟跌 → 外部压力传导中。
- **板块强弱差**：最强板块（如浪潮+1.94%）和最弱板块（如东财-4.20%）相差 >5% 时说明市场极度分化，非普涨/普跌。
- **情绪温度计三色体系**：
  - 🟢 绿色：正常或偏暖（量能正常、蓝筹撑盘、科技独立）
  - 🟡 黄色：中性偏弱（小幅普跌、量能中等、但无恐慌）
  - 🔴 红色：警示（放量暴跌、北向流出、小盘恐慌杀跌）
- **明日预判必须有概率标记**：基准情景(65%) / 乐观(20%) / 悲观(15%)，让用户理解这不是单点预测而是情景分析。

#### 报告产出速度要求

- 数据采集：控制在 4-5 次工具调用以内
- 优先顺序：指数(1次curl) → 热股(1次批量curl) → 外围(browser扫描) → web_search(可选，1次)
- 若 push2 板块API失败或 browser 页面无法提取表格 → **立即切换到热股情绪代理法**，不要在死路上浪费工具调用次数
- 全部数据分析时间：不超过 30 秒（从开始到输出完整报告）
- **如果某一步超时（如 web_search >15秒），跳过该步，基于已有数据做判断即可**

#### 报告交付（可选）

当用户要求将报告发送到飞书时：
- **纯文本**: 用 `hermes send -t feishu:oc_...` 发送
- **PDF 附件**: `hermes send -f` 不支持二进制文件。需用 Feishu API 直接上传：获取 tenant token → 上传文件 → 发送 file message。详见 `references/feishu-pdf-report-delivery.md`

## 📋 盘前简报工作流（08:30 定时任务）

### 与每日市场扫描的区别

| 维度 | 盘前简报（本节） | 每日市场扫描（上文） |
|:----|:----------------|:-------------------|
| 触发时间 | 08:30（盘前） | 09:25（开盘后） |
| 输出产物 | 隔夜外围 + 昨日回顾 + 今日关注 | 大盘走势 + 情绪验证 + 明日预判 |
| 数据来源 | premarket JSON + portfolio JSON + web_search + MCP实时 | 腾讯API + 热股代理 + 外围扫描 |
| 持仓处理 | 缓存数据 + MCP补充实时价 | 可不涉及持仓 |

### 数据采集步骤（4-6次工具调用）

#### Step 1: 读本地缓存（2次）

```python
# 1a. 盘前数据
cat ~/.hermes/data/premarket/YYYY-MM-DD.json
# 1b. 持仓数据
cat ~/.hermes/data/portfolio/current.json
# 1c. 最新收盘快照
ls -1t ~/.hermes/data/market_snapshots/ | head -1
cat ~/.hermes/data/market_snapshots/最新文件.json
```

**注意**：
- `premarket.json` 的 `a_share_yesterday` 和 `hot_sectors` 字段可能为空 → 不要停，下一步用 web_search 补
- `portfolio/current.json` 的更新日期可能早于今日 → 用 MCP `get_stock_quote` 拉实时价重算浮盈
- `market_snapshots/` 可能有缺失交易日（如 cron 未运行）→ 用 web_search 补

#### Step 2: MCP 补充实时数据（2-3次）

```python
# 2a. 板块资金流向
mcp-eastmoney sector_fund_flow(kind="industry", limit=10)
# 2b. 主力资金排行
mcp-eastmoney main_fund_rank(market="all", limit=10)
# 2c. 持仓实时价（批量，1次调用/股，控制在4-6次）
mcp-eastmoney get_stock_quote(code=...)  # 逐一查持仓
```

#### Step 3: web_search 新闻（4次，并行）

每个重点方向搜索1-2条最新新闻：
- "AI算力 半导体 最新 日期"（替换为当天日期数字）
- "机器人 最新动态"
- "电网设备 利好"
- "A股 昨日 收盘 上证 成交额"（补 premarket 空缺）

**失败处理**：web_search 超时（>15秒）或返回无关结果时，跳过该方向，用已有数据判断。

#### Step 4: browser_navigate 补采集（按需）

当 web_search 返回的页面描述不够详细时，用 `browser_navigate(url)` 打开具体收评页面：
- 东方财富/财联社每日收评：涵盖指数涨跌、板块轮动、成交额、热点个股
- 新浪财经收评：有散户评论区情绪参考

```
# 📋 盘前简报 · YYYY年MM月DD日（周X）

## 隔夜外围
[美股三大指数涨跌 + 解读]
[亚太主要市场涨跌 + 解读]

## 今日关注

[每个方向给出看好/观望/回避的判断]

## 风险提示
[当日需要注意的风险点]

## 持仓参考
[基于外围和新闻，今日四只持仓的应对思路]
[重点关注深度浮亏标的的走势]
```

### Pitfalls

- **premarket JSON `a_share_yesterday` 为空**：不要跳过昨日A股回顾。用 web_search "A股 昨日日期 收盘 上证 成交额" 补数据，然后用 browser_navigate 打开某篇收评文章提取完整数据（指数涨跌幅、成交额、热点板块、大跌板块）
- **portfiolio 数据过时**：`current.json` 日期若早于今日，必须用 MCP `get_stock_quote` 拉实时价重算每只的浮盈/浮亏。不要直接引用缓存中的旧价
- **web_extract 后端限制**：当 `web_extract` 因 extract_backend=ddgs 失败时，用 `browser_navigate` 替代。东方财富/财联社的收评页面含最完整数据
- **方向新闻覆盖不全**：能搜到3个方向就不必强求第4个。标注"数据暂缺"比编造好
- **持仓盈亏计算**：先确定持股数（market_val ÷ last_price 取整），再用实时价 × 股数 - 总成本 = 真实盈亏。不要直接用缓存里的 pnl_pct

## 数据源可靠性矩阵（2026-07 实测）

| 数据源 | 可靠性 | 用途 | 注意事项 |
|--------|:------:|------|---------|
| `qt.gtimg.cn` (腾讯) | ⭐⭐⭐⭐⭐ | 指数+个股实时行情 | 字段[3]=现价、[33-34]=当日高/低、[47-48]=年线高/低（⚠️ 不是90日，是52周年线区间）、[37]=成交额(万)、[38]=换手率、[39]=PE、[43]=振幅。**字段[51-53] MA值仅对指数可用，对个股完全不可信**（如江苏雷利 MA10 返回68.13 但现价30.81）。MA值必须用K线数据计算或用新浪API验证 |
| `hq.sinajs.cn` (新浪) | ⭐⭐⭐⭐ | 个股实时行情替代 | 需 `-H "Referer: https://finance.sina.com.cn"`。返回字段：今开/昨收/现价/最高/最低/成交量/成交额。**成交额单位是元（不是万）**，与腾讯API不同 |
| `push2.eastmoney.com` HTTP | ⭐ | 板块排行 | HTTPS不可用（证书问题）。**`clist/get` 已完全封锁（2026-07确认）**，所有t={1,2,3,4}均返回空响应。不要再尝试此端点。改用热股情绪代理法 |

| `web.ifzq.gtimg.cn` (腾讯K线) | ⭐⭐⭐⭐ | K线数据/均线计算 | 需 `-sL` 处理302 redirect。参数格式：`param={mkt}{code},day,,,N` |
| 东方财富 browser 页面 (boardlist) | ⭐⭐⭐ | 板块排行 | `boardlist.html` → redirect 到 `gridlist.html`，页面加载后表格不在 DOM 中。点击\"概念\" tab 有时能加载但不可靠 |
| `web_search` | ⭐⭐ | 新闻催化验证 | 慢（5-15秒），搜索当日热点板块时返回结果有时效性偏差 |
| **mcp-eastmoney** (MCP server) | ⭐⭐⭐⭐⭐ | **板块排行、资金流向、个股行情、K线** | **新增 PREFERRED 数据源！** `sector_fund_flow` 替代已封锁的 push2 clist，返回行业/概念板块涨跌幅+主力净流入+领涨股。`main_fund_rank` 批量获取主力资金排行。无 API Key，零配置 |
## 同板块个股背离诊断（节奏错位分析）

用户常见问题：\"XX股和XX股不是一个方向吗，为什么一个涨一个跌？\"

**核心原因**：同板块个股的**节奏错位**。A股市场信息传导到每只个股的速度、力度、持续性不同，导致同板块内个股的涨跌节奏不同步，这**不是背离，是错位**。

### 诊断六步法

```
Q: 中科曙光今天-1.12%，浪潮信息+1.94%，同属AI算力为什么不跟？
```

**Step 1: 拉近10日K线对比**
```
          中科曙光        浪潮信息
6/25  86→97 (+5.18%)   64→68 (+5.51%)
6/30  98→107 (+9.41%)  65→70 (+7.35%)
       ↑ 急涨24%后见顶    ↑ 稳步爬升
7/1   冲高109→回落     冲高71→回落
7/3   93→92 回调      63→66 反弹
7/7   93→93 横盘      69→71 继续涨
```

**Step 2: 判断谁先「跑」了**

看近5-10个交易日的**累计涨幅**。如果一只股在3-5天内涨了20%+而另一只没跟，说明前者提前反映了利好，处于**回调消化期**；后者在**补涨爬升期**。

**Step 3: 判断回调阶段**

对提前跑的那只：
- 从最高点跌了多少？（中科曙光109.60→93.50，回调-14.7%）
- 低点是否在抬高？（前日91.20→今日92.74，是的话说明企稳中）
- 是否缩量？（放量跌=恐慌，缩量跌=自然消化）

**Step 4: 分析资金选择偏好**

为什么资金优先选另一只？
- 绝对价格更低（浪潮71元 vs 中科曙光93.5元 → 性价比更高）
- 年线位置更低（浪潮60% vs 中科曙光44%→已涨过一波需要消化）
- 换手率更高（浪潮7.03% vs 中科曙光4.10%→活跃度更高）
- 近期走势更平滑（震荡上行 vs 急涨急跌→资金更安心）

**Step 5: 结论公式**

```
节奏错位结论 = 
如果 A 先涨了24%后回调14%，B 涨了11%还在爬升
→ A 在「回调消化期」，B 在「补涨爬升期」
→ 等 A 回调到支撑位企稳，或等 B 涨完进入消化期
→ 两者的产业逻辑没有变，只是入场时机不同
```

**Step 6: 操作推论**

| 场景 | 操作 |
|------|------|
| 你持有A（已回调的股），B在涨 | 别担心，等A回调结束。K线低点抬高+缩量=企稳信号。**不要在A亏钱时割肉去追B** |
| 你想买这个方向 | 选**正在爬升的那只**（B），不要买高位回调的那只（A）。等A回调充分再考虑 |
| 两只都在涨，一只快一只慢 | 正常。快的那只先到阻力位会回调，慢的那只随后补涨 |

### 经典案例

**案例：中科曙光 vs 浪潮信息（2026-07-07）**
```
同板块：AI算力/服务器
中科曙光：4天涨24%（6/25-6/30），之后回调-14.7%
浪潮信息：震荡上行11%（6/25-7/7），仍在爬升

用户问：\"中科曙光为什么不跟浪潮信息？\"
诊断：中科曙光提前跑完了一波，在回调消化期
     浪潮信息在补涨爬升期
     两者节奏错位，不是逻辑背离
```

## Pitfalls

- **Boardlist URL redirect**: 东方财富 `boardlist.html` 重定向到 `gridlist.html`，导致浏览器提取板块排行失败。不要死磕这条路，改为使用热股情绪代理法（Step 3）。
- **f-string conditional formatting**: Python f-string 内联条件表达式如 `{leader if leader else "-"}` 在包含格式符时（如 `:12s`）会报 SyntaxError。必须用三元表达式先计算变量再格式化。
- **外围数据时效性**: 东方财富行情页面的全球股市数据可能有延迟，仅用作方向性参考而非精确数据。
- **不要同时发多个大工具调用**: 每日扫描涉及 3-4 次工具调用（指数 + 热股 + 外围 + 搜索），控制在 4 次以内。如果某一步超时，跳过直接基于已有数据做判断。
- **腾讯 MA 字段仅对指数可用**: `qt.gtimg.cn` 字段[51-53]（MA5/MA10/MA20）对**个股完全不可信**（如江苏雷利 现价30.81 但返回 MA10=68.13）。须用腾讯K线API自行计算均线。对指数（如上证）该字段是准确的。
- **东财资金流向页面 iframe 陷阱**: `data.eastmoney.com/bkzj/hy.html` 表格在 iframe 内动态渲染，browser_console 无法访问。不要尝试从中提取结构化数据。
- **Tencent 年线 vs 90日线混淆**: 字段[47-48] 返回的是**52周（约1年）**最高/最低价，不是90日区间。**建议统一使用年线区间计算相对位置**，避免混淆。
- **Sina API 单位差异**: 成交额单位是**元**（腾讯是**万**），万级单位需除以10000对比。
- **用户要「完整报告」不是「快筛」**: 当用户明确说「出一份完整的报告」时，不要用「全市场扫描快速通道」的两阶段法。应该一次性输出包含大盘/资金/方向/个股/明日预判的完整报告。
