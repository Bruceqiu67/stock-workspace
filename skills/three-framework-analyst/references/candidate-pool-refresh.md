# 候选池刷新方法论

> 首次手动刷新：2026-07-13 | cron: f20f94900f74（月首16:00）

## 刷新步骤

1. **MCP 板块扫描**：sector_fund_flow(kind="industry", limit=20) + sector_fund_flow(kind="concept", limit=20)
2. **主力资金排行**：main_fund_rank(limit=30) — 看资金去哪了
3. **三框架分析**：综合资金流+产业链+研究方法论，选出 8-12 个方向
4. **个股筛选**：每个方向 4-7 只代表股

## 两层候选结构（I1）

候选池分为两层，刷新时必须分开维护：

| 层 | 定义 | 维护方式 |
|:--|:--|:--|
| 全市场宇宙 | 指数成分 + 行业龙头 + 成交额/流动性筛选 | 写入 `~/.hermes/data/candidate_universe.json`，可每日/每周更新 |
| 重点观察池 | 当前重点跟踪的 9 个方向 / 39 只标的 | 维护 `scripts/candidate_universe.py` 的 `WATCHLIST`（月度刷新） |

- 每只观察池标的必须带 `inclusion_reason`（纳入原因）、`included_at`（纳入日期）、`exit_criteria`（退出条件）。
- 缺少全市场宇宙配置时，候选扫描会标记 `universe_status=watchlist_only`、`selection_bias_risk=high`；报告不得把观察池排序写成“全市场选股”。
- 刷新后用基准（沪深300/中证1000）对比观察池表现，评估池子的选择偏差，而不是只看池内排名。

## 个股筛选标准（FilterPolicy）

阈值由 `scripts/filter_policy.py` 按用途（观察池/交易池）和市场状态统一提供，不再散落在文档与脚本中：

| 维度 | 标准 |
|------|------|
| 价格 | 观察池硬上限 150 元（>100 元标记惩罚）；交易池硬上限 100 元 |
| 位置 | 52周相对位置 ≥70% 硬淘汰；60%-70% 排序惩罚；<40% 优先 |
| 换手率 | 活跃，不是僵尸股（人工/软性标准，当前未做硬过滤） |
| 覆盖面 | 龙头+弹性标的兼顾（人工标准） |
| 方向级 | 方向内全部空头排列（MA5<MA10<MA20）时整方向放弃（`filter_policy.py` 执行） |
